# 自定义夜间模式 / 护眼叠加（WarmOverlay）

Windows 11 自带的「夜间模式」失效时的备用方案。一个 24 KB 的单文件托盘程序，用来降低屏幕蓝光、给屏幕加暖色。

**与同类工具的关键区别：截图和录屏不会被染色。** 见下方[设计](#设计为什么截图不会变色)。

```
WarmOverlay.exe        托盘程序（单文件，无依赖）
config.ini             配置，与 exe 同目录
ramp_____DISPLAY1.txt  显示器基线色彩曲线（自动生成，勿手动编辑）
```

## 问题背景

本机 Win11 自带的夜间模式不生效（通常由 HDR 或「自动管理颜色」抢占显示管线导致），所以写了这个备用工具。

但初版用**全屏半透明叠加窗口**实现，出现了截图偏色的问题：

> 屏幕上看着是暖的，截出来的图也是暖的 —— 发给别人的截图颜色和实际看到的不一致。

这是叠加层方案的固有问题：它把色块真实画在了画面上，截图 API 抓到的自然包含它。

## 设计：为什么截图不会变色

Win11 自带的夜间模式走的是**显示器 gamma 曲线**（`SetDeviceGammaRamp`），在 GPU 输出端调色，帧缓冲里的像素数据本身没变，所以截图永远是原始颜色。本工具改用同一机制作为主方案。

实测对比（对桌面区 378,400 个采样点逐像素比对）：

| 场景 | 截图差异 |
|---|---|
| 开启 vs 关闭护眼（旧版，叠加层） | 明显偏暖，RGB 平均差约 4 级 |
| 开启 vs 关闭护眼（新版，色彩曲线） | **0.006 级，即完全一致** |

双引擎设计：

| 模式 | 实现 | 截图是否染色 | 适用场景 |
|---|---|---|---|
| **色彩曲线**（主） | `SetDeviceGammaRamp` 写显示器 LUT | 否 | 默认；原理同系统夜灯 |
| **叠加层**（回退） | 全屏窗口 + `WDA_EXCLUDEFROMCAPTURE` | 否 | HDR / 自动管理颜色开启时 |

第二方案也做了处理：叠加窗口设置 `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)`（Win10 2004+），窗口在屏幕上看得到，但在任何截图/录屏 API 中都不可见。

**自动模式**会先检测显示管线状态：若 HDR 或「自动管理颜色(ACM)」正在生效，gamma 曲线会被驱动静默忽略，此时自动切到叠加层。

## 使用

双击 `WarmOverlay.exe` 启动，托盘出现橙色「暖」图标。双击图标打开设置。

### 设置项

| 项目 | 说明 |
|---|---|
| 启用护眼 | 总开关 |
| 强度 | 0–60%，暖色叠加的程度 |
| 暖度 | 0–100，越大越偏橙红 |
| 着色方式 | 自动 / 色彩曲线 / 叠加层 |
| 开机自启 | 写入 `HKCU\...\CurrentVersion\Run` |

设置窗口底部会实时显示当前实际生效的方式，例如：

```
当前：色彩曲线（同系统夜灯原理，截图不失真）
```

### 快捷键

| 快捷键 | 功能 |
|---|---|
| `Ctrl+Alt+0` | 开关护眼 |
| `Ctrl+Alt+↑` | 强度 +2% |
| `Ctrl+Alt+↓` | 强度 −2% |
| `Ctrl+Alt+W` | 暖度循环（+20，超过 100 归零） |

### 命令行

托盘程序本身不带参数。重复启动不会产生第二个实例，而是唤出设置窗口（单实例互斥体 + 命名事件）。

## 配置

`config.ini` 与 exe 同目录：

```ini
Strength=0.06
Warmth=15
Enabled=1
Mode=1
```

| 键 | 取值 | 说明 |
|---|---|---|
| `Strength` | 0 – 0.6 | 强度（浮点，invariant culture） |
| `Warmth` | 0 – 100 | 暖度 |
| `Enabled` | 0 / 1 | 开关 |
| `Mode` | 0 / 1 / 2 | 0=自动 1=色彩曲线 2=叠加层 |

读取时会做范围校验，越界值自动夹紧。

## 健壮性

gamma 曲线是**全局显示状态**，程序异常退出会留下残色（整块屏幕一直偏暖）。本工具做了三层防护：

1. **基线持久化** —— 首次见到某显示器时，把它当时的原始曲线存到 `ramp_<device>.txt`。
2. **启动自愈** —— 启动时若发现当前曲线只是基线的线性变换（说明是上次残留的暖色），自动还原；若是用户换了校准/ICC，则以当前为准并更新基线。
3. **退出还原** —— 正常退出、`Application.Exit()` 都会还原曲线。

另有 5 秒巡检：驱动重置、独占全屏切换会覆盖 gamma 曲线，巡检只在检测到曲线被改掉时才补写，避免无谓重写造成闪烁。

> 已知限制：**强制结束进程（任务管理器结束任务 / 强杀）无法拦截**，屏幕会残留暖色。重新启动程序即自动清除。

## 编译

需要 Windows 自带的 .NET Framework 4.x（Win10/11 默认已装），无需 Visual Studio 或 .NET SDK。

```powershell
# 编译到当前目录
.\build.ps1

# 编译并部署（自动停掉旧进程）
.\build.ps1 -Install -InstallDir 'E:\Tool\自定义夜间模式'
```

脚本会自动定位 `Framework64\v4.0.30319\csc.exe`，找不到时回退到 32 位版本并给出明确提示。

产物为 `anycpu` + `optimize+` 的单文件 winexe，约 24 KB。

## 已知限制

- **HDR / 自动管理颜色开启时色彩曲线无效**，会自动回退到叠加层。这是驱动行为，非本工具可控。
- **独占全屏游戏**（DirectX exclusive fullscreen）可能不受 gamma 曲线影响。
- 使用**显示器硬件校准/ICC 配置**的用户，开启后校准结果会失效，做设计时应关闭。
- 强制结束进程会残留暖色，重启程序自愈。
- 仅测试于单显示器环境（`\\.\DISPLAY1`）。多显示器代码路径已实现（`EnumDisplayDevices` 枚举所有活动显示器），但未实测。

## 技术要点

| 点 | 说明 |
|---|---|
| 曲线读写 | `GetDeviceGammaRamp` / `SetDeviceGammaRamp`，每通道 256 项 `ushort` |
| 混合公式 | `out = (1-s)·base + s·tint`，与叠加层 alpha 混合等价 |
| 暖色计算 | `R=255`, `G=210−90t`, `B=150−130t`，`t = Warmth/100` |
| ACM/HDR 检测 | `QueryDisplayConfig` + `DisplayConfigGetDeviceInfo(GET_ADVANCED_COLOR_INFO)`，判据是 bit1（已启用）；bit2 是「强制宽色域」，Intel 在 SDR 下也会置位，**不能**作为判据 |
| 截图排除 | `SetWindowDisplayAffinity(hwnd, 0x11)`，即 `WDA_EXCLUDEFROMCAPTURE` |
| 点击穿透 | `WS_EX_TRANSPARENT \| WS_EX_TOOLWINDOW \| WS_EX_NOACTIVATE` |
| 置顶维持 | 2 秒定时 `SetWindowPos(HWND_TOPMOST)` |
